# Use cases apply policy in domain language

The learner understands that a use case should express an application goal and work with domain concepts, not provider vocabulary. They can distinguish adapter translation, domain invariants, and use-case policy, and understand that loading slate data and evaluating quarterbacks may become separate use cases.

## Evidence

The learner correctly classified the responsibilities in the Lesson 10 scenario quiz and explained that use-case independence allows DraftKings terminology and format to change without changing application policy.
