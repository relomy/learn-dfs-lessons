# Boundary normalization protects domain meaning

The learner understands that identity resolution determines which records refer to the same player, while boundary normalization translates provider-shaped data into stable, domain-owned evaluation input. They understand that provider field names, string-encoded numbers, currency formatting, and transport details should be handled by the adapter rather than the evaluator.

They also understand that a missing value is not the same as zero: missing passing attempts should remain explicitly unknown so the evaluation policy can decide whether the player is evaluable.

## Evidence

The learner correctly answered the Lesson 14 quiz and applied the concept to a DraftKings record, identifying that `"$7,400"` should become numeric `7400` while omitted passing attempts should remain unknown rather than become `0`.
