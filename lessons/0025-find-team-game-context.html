Find team game context

Match a candidate's team code to a game context, while making a missing match visible.

A join may not succeed

A quarterback with team: "HOU" should receive Houston's team context. But a slate may not contain Houston's game, or a source may use an inconsistent code. Returning undefined would make every caller invent its own missing-data behavior. Model the two possible outcomes instead.

export type TeamContextLookup =
  | { readonly kind: "found"; readonly context: TeamGameContext }
  | { readonly kind: "missing"; readonly team: string };

Red: name both outcomes

Add tests in test/vegas.test.ts for a function named findTeamGameContext. Use two contexts derived from the familiar BUF at HOU line.

The successful lookup should be exact:

assert.deepEqual(findTeamGameContext("HOU", contexts), {
  kind: "found",
  context: {
    team: "HOU",
    opponent: "BUF",
    gameTotal: 48,
    impliedTeamTotal: 25.5,
  },
});

Then describe a team absent from that game:

assert.deepEqual(findTeamGameContext("DAL", contexts), {
  kind: "missing",
  team: "DAL",
});

Green: one lookup, two explicit results

Put the type and function in src/vegas.ts. The function takes only what it needs:

export function findTeamGameContext(
  team: string,
  contexts: readonly TeamGameContext[],
): TeamContextLookup

Use contexts.find to look for a context with the same team. If it returns undefined, return the missing variant. Otherwise return the found variant and preserve the matched context.

Use the result safely

A later caller will pass candidate.team. Its branch on kind makes TypeScript narrow the union:

const lookup = findTeamGameContext(candidate.team, contexts);

if (lookup.kind === "missing") {
  // lookup.team is available here
} else {
  // lookup.context is available here
}

Do not change QuarterbackCandidate or evaluateQuarterback in this lesson. You are building a lookup with an honest result, not deciding how context changes a score.

Explain the result

  1. Why is missing a better result than returning a zero-valued team context?
  2. Why does findTeamGameContext take a team string rather than an nflverse row?
  3. What does checking lookup.kind let TypeScript know?

Primary source

Read TypeScript's narrowing guide. A literal kind check lets TypeScript identify the properties available in each union branch.

Done when

One test finds Houston's context, one returns an explicit missing result for Dallas, and no missing lookup becomes a fake scoring projection.

Ask if the find return type feels strange. It is the exact point where the result union earns its keep.
