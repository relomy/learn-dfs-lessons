Lesson 13 · DFS analytics architecture

Match identities across sources

Combine data without confusing provider IDs with player identity.

The idea

When salary, matchup, and statistics arrive from different sources, the system must decide which records refer to the same real-world player. A DraftKings ID identifies a record within DraftKings; it does not automatically identify the player across every provider.

Identity rule:
A source identifier is evidence about identity, not necessarily the domain identity itself.

Keep the identities distinct

  • Canonical player identity: the application’s way of referring to the real player.
  • Source identity: a provider’s identifier, such as a DraftKings ID or statistics-provider ID.
  • Match decision: a deliberate link between source records and a canonical player.

Name matching can be useful evidence, but names can vary by punctuation, suffix, spelling, or updates. An uncertain match should be represented as uncertain or left unmatched rather than silently joining the wrong player.
