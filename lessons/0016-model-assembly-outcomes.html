Lesson 16 · DFS analytics architecture

Model assembly outcomes

Make the next action clear when records form a candidate, need review, or cannot form one.

The problem with a simple failure signal

Suppose candidate assembly returns false or null. The caller knows no candidate came back, but not whether it should ask for a review, show a data-quality error, retry later, or simply stop. Those outcomes lead to different actions.

Result rule:
Return the next action, plus only the context that action needs.

Three explicit results

Ready (Pass)
A domain candidate
Needs review (Hold)
Reason and source references
Rejected (Drop)
Reason and invalid input context

These are not three error messages. Ready continues to evaluation. Needs review waits for a decision that may change later. Rejected records why this input cannot create a candidate under the current contract.

What belongs in each result?

  • Ready: the candidate, including any intentionally unknown evaluation inputs.
  • Needs review: a reason code and the source record references needed to resolve the match.
  • Rejected: a reason code and the offending source reference. Do not attach a half-valid candidate.

Practice the result shape

For each case, choose the result that lets the next component act safely. The cards name the information the result must carry. In guided mode, read the reason after each answer. Then try blind mode and aim for five correct.

Transfer check

A caller receives NeedsReview for an ambiguous name match. What information must it receive besides the word “ambiguous,” and why would null be a poor replacement?

Primary source

Read the Data Contract Specification with this question in mind: what must a consumer know when a contract cannot be satisfied? The same concern applies inside an application. The result must preserve the information the next step needs.

Done when

You can choose Ready, Needs review, or Rejected and name the minimum information each result carries.

Ask follow-up questions whenever two outcomes seem close. Explain the next action that separates them.
