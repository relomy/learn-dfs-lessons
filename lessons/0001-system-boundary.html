Lesson 1 · DFS analytics architecture

Draw the system boundary

Before choosing modules, classes, or databases, decide what the system promises to do.

The idea

A system boundary separates responsibilities. Inside the boundary, our system owns decisions and rules. Outside it, sources and users interact with the system through defined inputs and outputs.

For this project, the first boundary is likely between external NFL data sources, our evaluation process, and the people who want a slate ranking.

Our current candidate:
The system acquires data for one NFL DFS slate, combines the relevant data, evaluates eligible players with a position-specific scoring model, and returns ranked players.

Your decision

Write a one-paragraph description of the first version. Include:

  1. what starts the process;
  2. what information the system acquires;
  3. what the system calculates; and
  4. what a user receives at the end.

Do not solve yet

Do not choose Python, an API framework, a database, or a folder structure. Those choices become easier after we know what the system must own.

Primary source

Read Martin Fowler’s explanation of bounded contexts. For now, focus on the idea that a model is valid within a particular boundary.
