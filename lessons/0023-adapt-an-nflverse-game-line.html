Lesson 23 · DFS analytics architecture

Adapt an nflverse game line

Translate one free provider record into the domain input that Lesson 22 already understands.

Keep the boundary honest

nflverse publishes a free game CSV with away_team, home_team, spread_line, and total_line. Its spread convention is the reverse of ours: a positive spread_line means the home team is favored. In our VegasGameLine, a negative homeSpread means the home team is favored.

Your job:
Make that sign change once, at the provider boundary. Do not make deriveTeamContexts learn nflverse's convention.

Start with a captured provider record

Create src/nflverse.ts. This interface belongs to the adapter because these are nflverse column names, not names the rest of the application should need to know.

import { type VegasGameLine } from "./vegas.js";

export interface NflverseGameRow {
  readonly away_team: string;
  readonly home_team: string;
  readonly spread_line: number | null;
  readonly total_line: number | null;
}

Use this fixture in the test. It represents an nflverse row where the home team is favored by three:

const row: NflverseGameRow = {
  away_team: "BUF",
  home_team: "HOU",
  spread_line: 3,
  total_line: 48,
};

Red: state the translation

Create test/nflverse.test.ts. Before implementing anything, write a test for a function named toVegasGameLine:

assert.deepEqual(toVegasGameLine(row), {
  awayTeam: "BUF",
  homeTeam: "HOU",
  gameTotal: 48,
  homeSpread: -3,
});

Run npm test. The missing function is the useful red result.

Green: translate, do not calculate

Implement toVegasGameLine. It should return a VegasGameLine and do only these four mappings:

awayTeam: row.away_team
homeTeam: row.home_team
gameTotal: row.total_line
homeSpread: -row.spread_line

TypeScript will make you face the two nullable line fields. Decide how this adapter reports an incomplete source row. Do not silently turn a missing line into zero. A thrown error is acceptable for this small slice; a result union may be useful later if callers need to recover.

Strengthen the test

  1. Add an away-favorite row. Its negative spread_line must become a positive homeSpread.
  2. Add a missing-total or missing-spread case. Assert the behavior you chose.
  3. Pass the successful adapter result into deriveTeamContexts in one small integration test. Houston should receive the larger implied total in the fixture above.

Why this source is first

It is public, free, and repeatable, which makes it a good source for learning and backtesting. It is not a promise of live odds. Scheduled future rows may exist before either line is populated. A live provider can become a separate adapter later without changing this translator or the derived-context calculation.

Explain the result

  1. Why is NflverseGameRow defined in the adapter rather than vegas.ts?
  2. Why does homeSpread: -row.spread_line belong in exactly one place?
  3. Why is a missing line different from a line of zero?

Primary source

Read nflverse's games data dictionary. It defines the game columns and documents the provider's spread sign convention.

Done when

Your adapter tests pass, missing lines cannot become a zero-valued game, and you can trace the one sign conversion from the provider record to VegasGameLine.

Ask before adding a live endpoint. We will decide whether its instability belongs behind a separate adapter.
