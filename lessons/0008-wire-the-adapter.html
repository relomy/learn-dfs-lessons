Lesson 8 · DFS analytics architecture

Wire the adapter

Keep the application independent while choosing a real source at the edge.

The idea

Dependency inversion means the useful application logic does not reach outward to construct or understand a DraftKings client. Instead, the application owns the PlayerSource contract, and an outer layer supplies an implementation of that contract.

Composition root:
The place where the application is assembled and its concrete dependencies are chosen.

Dependency direction

application defines PlayerSource
          ↑
DraftKings adapter implements PlayerSource
          ↑
composition root chooses the adapter

The arrows show who depends on the contract. The use case can ask a PlayerSource for slate players without knowing whether the source is a DraftKings CSV, another provider, or an in-memory test source.

Why wiring matters

If the use case constructs the DraftKings adapter itself, provider knowledge has moved inward. If the composition root supplies the dependency, the use case remains focused on its job and the adapter can be swapped without changing application policy.
