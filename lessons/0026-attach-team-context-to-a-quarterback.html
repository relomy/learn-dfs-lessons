Lesson 26 · DFS analytics architecture

Attach team context to a quarterback

Combine a candidate and its matched game context into one value that later policy can use.

Compose the two prior steps

Lesson 24 gave the quarterback a team code. Lesson 25 looks up that team in the two contexts derived from a game line. This lesson names the useful result of a successful match: a quarterback with the game context relevant to their team.

Quarterback candidate
team: "HOU"
+
Team contexts
BUF, HOU
→
QB context result

Name the result

Create src/quarterback-context.ts. Its public result keeps both outcomes explicit:

export type QuarterbackContextResult =
  | {
      readonly kind: "context-ready";
      readonly candidate: QuarterbackCandidate;
      readonly gameContext: TeamGameContext;
    }
  | {
      readonly kind: "missing-game-context";
      readonly candidate: QuarterbackCandidate;
      readonly team: string;
    };

The candidate appears in both variants. Even when context is missing, we still know which quarterback needs attention.

Red: describe the successful pairing

Create test/quarterback-context.test.ts. Use a complete HOU quarterback candidate and contexts derived from BUF at HOU with a total of 48 and a home spread of -3.

Write a test for attachTeamGameContext(candidate, contexts) that expects:

{
  kind: "context-ready",
  candidate,
  gameContext: {
    team: "HOU",
    opponent: "BUF",
    gameTotal: 48,

Then describe the missing match

Use the same two contexts with a candidate whose team is "DAL". Expect:

{
  kind: "missing-game-context",
  candidate,
  team: "DAL",
}

Run npm test. The missing module or function is the useful red feedback.

Green: map the lookup result

Import findTeamGameContext and call it with candidate.team. Branch on lookup.kind:

const lookup = findTeamGameContext(candidate.team, contexts);

if (lookup.kind === "missing") {
  return {
    kind: "missing-game-context",
    candidate,
    team: lookup.team,
  };
}

return {
  kind: "context-ready",
  candidate,
  gameContext: lookup.context,
};

This function returns a new value. It does not mutate candidate or add a context field to the existing candidate type.

Why keep the evaluator unchanged?

Context availability and context scoring are different decisions. This lesson makes context available to a future policy. The next lesson can decide which concrete game-total or implied-total rule belongs in that policy.

Explain the result

  1. Why does the missing-context result keep the candidate as well as the missing team?
  2. Why does this function return a new result instead of mutating QuarterbackCandidate?
  3. Why is it useful to separate attaching context from deciding whether that context is favorable?

Primary source

Revisit TypeScript's narrowing guide. The lookup result narrows into the two return shapes in this function.

Done when
