Use-case routing

The use case reads an application result and sends it to the next collaborator.

Coordination rule:
The use case chooses the next operation. The called component owns how that operation works.

Route each assembly outcome

Ready        → evaluation policy
NeedsReview  → review queue
Rejected     → diagnostics sink

Keep these responsibilities separate

  • Route: the use case calls the appropriate port or policy.
  • Score: the evaluation policy applies quarterback scoring rules.
  • Shape: the presenter turns an application result into CLI, API, or UI output.

The test

If replacing the UI changes the use case, presentation has leaked inward. If changing the quarterback formula changes the routing branches, scoring has leaked outward.
