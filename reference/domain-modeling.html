Domain modeling

A compact reference for turning a problem into a shared vocabulary.

Core idea

A domain model names the concepts and rules that matter to the problem. It is a communication tool and a foundation for the software design.

Useful questions

  • What does the user ask the system to do?
  • What facts must be known to do it?
  • Which words have precise meanings?
  • Which rules change the result?
  • Which concepts belong to this system, and which arrive from elsewhere?

Warning

Do not turn every noun into a class. A concept earns a place in the model when it has meaning, behavior, identity, or a rule attached to it.
