Boundary normalization

Translate provider-shaped data into application-owned meaning before it reaches the evaluation core.

Boundary rule:
External formats may vary; domain meaning should remain stable.

Pipeline

raw source record → adapter → normalized domain input → evaluator

Normalize here

  • field names and nesting
  • types, units, and representations
  • identity references
  • missing, invalid, and unavailable values

Do not leak

  • provider DTOs or column names
  • provider-specific status codes
  • transport details
  • silent guesses about missing data

Useful distinction

Zero means the measured value is zero. Missing means the value is not available. They must not be normalized to the same thing.
