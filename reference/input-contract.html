Input contracts

An input contract says what a source promises and what our system requires.

A contract covers

  • shape: which fields exist;
  • meaning: what each field represents;
  • quality: valid types, values, and completeness;
  • freshness: when the data describes; and
  • failure behavior: what happens when the promise is broken.

Four useful categories

  • Required: without it, the system cannot create a valid entry.
  • Optional: useful when present, but not needed for the current behavior.
  • Source metadata: needed to interpret or audit the input, but not part of the domain result.
  • Derived: calculated by our system rather than copied from the source.

Primary reading: RFC 4180.
